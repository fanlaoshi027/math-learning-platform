# 网站开发接班提示词

项目：`fanlaoshi027/math-learning-platform`
分支：`main`

## 开始前必须读取

1. `wp/wp-content/网站开发备忘录.md` —— 项目总规范、产品需求、技术架构、UI 原则。
2. `wp/wp-content/网站开发进度/00-项目状态.md` —— 当前状态、正在做什么、待办、最近 Commit。
3. `wp/wp-content/网站开发进度/README.md` —— 进度分卷规则；再读取当前编号最大的开发记录分卷。

## 接班规则

- 以《网站开发备忘录.md》为最高产品/技术规范。
- 从 `00-项目状态.md` 记录的断点继续，不重新开始，不擅自改变方向。
- 先检查 Git `main` 最新代码，再阅读相关代码和调用关系。
- Tutor LMS 4.0.4 是底层 LMS；MathCourse 是业务层，不重新制造完整 LMS。
- Tutor 相关底层调用优先通过 `MathCourse\Tutor\Adapter`。
- 权限统一由 `Access_Service` 决定。
- 学习进度统一由 `Progress_Service` 管理。
- 视频统一经过 `Course_Service` / `Video_Router`；未授权绝不能获得受保护 HLS 地址。
- 播放到几分几秒与课时完成必须分开保存。
- 不擅自增加备忘录没有要求的复杂功能。

## 每次开发必须执行

1. 读取上述文档和最新开发记录。
2. 检查当前代码与 Git。
3. 找到当前最重要的问题并修改。
4. 检查 PHP / JS / CSS / WordPress Hook / nonce / capability / AJAX / REST / Tutor 兼容性及权限绕过。
5. 修改完成后提交 GitHub `main`。
6. **立即更新 `wp/wp-content/网站开发进度/00-项目状态.md`。**
7. **把本次详细记录追加到当前开发记录分卷。**
8. 如果当前分卷达到约 20～30 KB，停止追加并创建下一卷。
9. 状态文件和开发记录也必须提交 Git。
10. 最终说明：完成内容、文件、Commit、当前状态、下一步、测试和风险。

## 进度文件结构

```text
wp/wp-content/
├── 网站开发备忘录.md
├── 网站开发接班提示词.md
└── 网站开发进度/
    ├── README.md
    ├── 00-项目状态.md
    ├── 01-开发记录.md
    ├── 02-开发记录.md
    └── ...
```

`00-项目状态.md` 永远保持小体积，只保存当前状态；历史全部放在分卷中，不覆盖、不删除旧卷。

## 核心架构

```text
WordPress
 → Tutor LMS Pro 4.0.4
 → Tutor\\Adapter
 → Course_Service
    ├→ Access_Service
    ├→ Progress_Service
    └→ Video_Router
 → 前台课程 / 学习页 / Video Player
```

如果不确定 Tutor API 或项目现有行为：先查代码和官方文档，不要凭记忆猜测。

**核心要求：先读规范和当前状态，再从 Git 当前断点继续；每次代码修改都必须写入 Git，并同步更新状态与开发记录。**
