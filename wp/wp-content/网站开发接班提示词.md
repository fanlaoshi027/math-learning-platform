1. `main/wp/wp-content/网站开发备忘录.md`

   **当前进度、最近修改、正在进行的任务、问题和下一步计划。**

# 接班工作流程

1. 读取上面两个 MD 文件。
2. 检查 `main` 最新 Git Commit。
3. 根据《网站开发进度.md》找到上次停止的位置。
4. 阅读相关代码和调用关系，不要凭猜测修改。
5. 严格遵守《网站开发备忘录.md》，不得擅自改变项目方向。
6. 继续当前最重要的任务，不要重新开始项目。
7. 修改代码后检查 PHP / JS / CSS / WordPress Hook / 权限 / 数据流 / Tutor LMS 兼容性。
8. 重点防止权限绕过、HLS 地址泄露、进度统计错误和移动端兼容问题。
9. 将代码修改真正提交到 GitHub `main`。
10. **代码提交后必须立即更新 `main/wp/wp-content/网站开发进度.md`。**
11. 进度文件更新也必须提交 Git。
12. 最终汇报：本次完成内容、修改文件、Commit、当前状态、下一步和发现的问题。

# 核心架构约束

WordPress
→ Tutor LMS 4.0.4
→ MathCourse 自定义插件
→ Theme 前台

Tutor LMS 是底层 LMS，不要重新开发完整 LMS。

MathCourse 负责本项目业务：

- 课程中心
- 学员授权
- 试看
- 课程访问权限
- 视频播放
- HLS 防盗链
- 学习进度
- 学员学习页面
- 教师专用后台

Tutor 相关底层调用优先统一经过：

`MathCourse\Tutor\Adapter`

不要让 Theme、Course、Video、Progress 等模块到处直接调用 Tutor API。

核心业务关系：

`Course Service` → `Access Service` → `Video Router` → `Player`

`Course Service` → `Progress Service`

未授权用户绝不能获得真实 HLS 播放地址。

播放位置和课时完成必须分开保存：

- 播放进度：当前播放到几分几秒
- 完成状态：课时是否完成

# 开发原则

- 极简、稳定、快速、现代、易维护。
- 手机、平板、电脑响应式。
- 深海蓝 + 活力橙、大圆角、卡片式 UI。
- Tailwind CSS 按既定项目规范使用。
- 不擅自增加错题本、笔记、社区等备忘录没有要求的功能。
- 不为了“代码漂亮”进行无关的大规模重构。
- 发现架构问题时，先分析影响，再修改。
- Tutor LMS API 不确定时先查项目代码/官方文档，不要凭记忆猜。

# 每次修改后的进度记录格式

必须在 `网站开发进度.md` 增加一条记录，至少包含：

- 日期
- Git Commit
- 修改文件
- 本次完成内容
- 修改原因
- 解决的问题
- 当前状态
- 尚未完成事项
- 下一步计划
- 测试情况
- 已知风险

记录必须足够详细，使没有参与过项目的其他开发者或 AI 能够从两个 MD 文件直接接手。
