## 一、项目定位

这是“樊老师数学”在线课程平台，基于 WordPress + Tutor LMS Pro 构建。

核心原则：

1. **Tutor LMS Pro 4.0.4 作为底层 LMS 驱动。**
2. MathCourse 负责网站自己的课程业务、权限、视频、学习进度和前台体验，但不重新制造一套完整 LMS。
3. Tutor LMS 原生课程、Topic、Lesson 数据结构继续作为课程数据源。
4. 通过 `Tutor\Adapter` 隔离 Tutor LMS API，业务模块尽量不要直接调用 Tutor API。
5. 课程权限统一由 `Access_Service` 决定，避免出现多套授权规则。
6. 学习进度统一由 `Progress_Service` 管理。
7. 视频播放统一经过 `Course_Service` + `Video_Router`，未授权时不得向前端返回受保护 HLS 地址。
8. 前台保持极简，不增加错题本、笔记、教师笔记、本节知识点、下载讲义等非核心功能。
9. HLS 采用 m3u8 + ts 碎片，并通过服务端签名网关隐藏真实视频源。
10. 每次代码修改必须写入 Git，并同步更新本进度文件。

### 核心数据流

```text
Tutor LMS 数据
      ↓
Tutor\Adapter
      ↓
Course_Service
      ├── Access_Service      → 判断是否可以观看
      ├── Progress_Service    → 计算学习进度
      └── Video_Router        → 生成受保护播放地址
      ↓
前台课程目录 / 学习页面 / Video Player
```

# 五、当前正在做什么

## 当前阶段：全站架构一致性检查

目标不是继续盲目增加功能，而是先确保已有功能之间不会互相绕过。

当前重点检查：

### A. Course

- Course ID 是否始终来自 Tutor。
- Lesson → Topic → Course 关系是否正确。
- 前台课程目录和后台 Tutor 课程结构是否一致。
- 草稿/私密/发布状态是否被正确处理。

### B. Access

必须保证：

```text
管理员
  → 可以观看

已授权学员
  → 可以观看授权课程全部课时

未授权用户
  → 只能观看明确设置为 Preview 的课时

Tutor Free/Public
  → 不能绕过 MathCourse 授权规则
```

### C. Video

必须保证：

```text
请求播放
   ↓
确认 Lesson
   ↓
确认 Course
   ↓
确认 Access
   ↓
确认 HLS 存在
   ↓
生成短期签名 URL
   ↓
m3u8 重写
   ↓
媒体片段再次鉴权
```

### D. Progress

必须保证：

- 只有实际有权限学习的用户才能产生完成记录。
- Preview 是否允许记录完成状态需要明确产品规则。
- 课程总课时不能因为草稿课时而错误增加。
- 课程排序改变后，进度百分比仍然正确。
- 删除课时后旧的 User Meta 不应该造成错误统计。

### E. Frontend

继续检查：

- 课程中心。
- 课程详情。
- 学习页面。
- Lesson 页面。
- 手机端。
- iPhone Safari。
- PC 浏览器。

确保没有重新出现之前已经明确删除的功能：

- 错题本
- 错题库
- 笔记
- 教师笔记
- 本节知识点
- 下载讲义
- 多余 Tutor 前台元素

# 七、开发规则（后续开发者必须遵守）

## 规则 1：先读本文件，再改代码

任何新的开发者或 AI 接手项目时，第一步：

1. 阅读本文件。
2. 阅读 `网站开发备忘录.md`。
3. 检查 Git 当前 `main` 最新 commit。
4. 再开始修改。

不能因为上下文丢失就重新设计一套架构。

## 规则 2：不要绕过 Adapter

如果需要访问 Tutor LMS 数据：

```text
错误：业务代码 → Tutor API

正确：业务代码 → Tutor Adapter → Tutor LMS
```

除非确实是 Tutor 集成层本身，否则不要直接调用 Tutor 内部函数。

## 规则 3：权限只有一个最终入口

```text
Access_Service
```

任何新的播放、课程访问、Lesson 访问接口，都必须经过统一权限判断。

## 规则 4：不要在前端暴露真实 HLS Origin

前端只能获得 MathCourse 保护后的播放地址。

不要在：

- HTML
- JS
- AJAX JSON
- REST JSON
- 页面源码

中直接输出真实 HLS Origin。

## 规则 5：每次代码修改必须同步更新本文件

每一次修改完成后：

1. 修改代码。
2. 检查代码。
3. Git commit。
4. **马上更新 `网站开发进度.md`。**
5. 再提交进度文件。
6. 在最终回复中告诉用户修改了什么、当前 commit、下一步做什么。

## 规则 6：发现问题优先修问题，不为了“看起来有进度”增加功能

当前阶段优先级：

```text
正确性
→ 权限安全
→ 播放稳定
→ 数据一致
→ 学习体验
→ 性能
→ UI细节
→ 新功能
```

## 规则 7：保持极简

这个项目是樊老师自己的数学课程网站，不是通用 SaaS LMS。

不要为了“功能丰富”加入复杂模块。
