# UI v2 迁移计划

> 目标：把 `wpthem/` 作为视觉参考，统一迁移到生产主题 `wp/wp-content/themes/math-course-theme/`；不替换 `wpthem`，不改变 `main`。

## 1. 硬性边界

- 所有本轮 UI 修改只提交到 `wpui-v2`。
- `wpthem/` 只作为视觉参考，不作为生产主题安装目录。
- 业务逻辑继续由 `wp/wp-content/plugins/math-course/` 承担。
- 不破坏 Tutor LMS 对课程数据的驱动关系。
- 不破坏 HLS、Video.js、播放倍速、全屏、播放进度与课时完成记录。
- 不增加错题本、笔记、教师笔记、本节知识点、下载讲义等非核心功能。
- 手机端优先，同时兼容微信内置浏览器、平板和桌面端。

## 2. 统一视觉语言

- 主色：深海蓝；强调色：橙色。
- 背景以浅灰/白为主，减少大面积渐变和装饰。
- 卡片采用较大圆角、轻边框、低强度阴影。
- 标题层级清楚，正文保持较高可读性。
- 交互控件保持统一高度、圆角、焦点态和触控区域。
- 课程封面支持真实图片，也支持纯色+文字封面；无图片时必须保持完整视觉质量。

## 3. 当前生产主题状态

当前主题已经存在多轮 UI 覆盖层，包括 `reference-ui.css`、`course-ui-polish.css`、`course-cover.css`、`course-card-v2.css`、`course-center-v2.css`、`learning-v2.css`、`header-v2.css` 等。后续不再继续无止境增加补丁层。

下一阶段采用“收敛而不是继续堆叠”的方式：

1. 先冻结现有功能和页面结构。
2. 抽取公共设计变量、容器、按钮、卡片、表单、状态、响应式断点。
3. 将首页、课程中心、课程详情、学习中心、学习播放器统一到同一套 token。
4. 删除已经被新规则完全覆盖、且无业务依赖的重复 CSS；删除前逐文件核对选择器。
5. `functions.php` 最终只保留必要的资源加载关系，不再继续添加同类 UI stylesheet。

## 4. 页面迁移顺序

### A. 全站壳层

- `header.php`
- `footer.php`
- `style.css`
- 公共 UI token / 基础组件

目标：桌面、手机、微信端拥有一致的页头、页脚、容器和间距体系。

### B. 首页

- `front-page.php`
- 首页课程卡片调用保持现有 shortcode/业务逻辑。

目标：视觉参考中的 Hero、知识体系入口、精选课程和 CTA 统一到 v2 token。

### C. 课程中心

- 课程筛选/目录
- 课程卡片
- 课程封面
- 课程详情

目标：课程卡片在有封面、无封面、纯色封面三种情况下均稳定；移动端单列/合理双列，不出现横向溢出。

### D. 学习页面

- 学习布局
- 课时列表
- 播放器
- 播放器底部控制栏
- 手机横屏/全屏

目标：保留现有播放功能，只做视觉和交互层收敛。进度条在视频底部始终可见；10 秒前进/后退、倍速、全屏等控件不能因 UI 重构丢失。

## 5. 验收清单

### 功能

- [ ] 未登录用户可以看到公开课程/试看内容。
- [ ] 已授权用户可以进入对应课程学习。
- [ ] 未授权课时仍受现有权限控制。
- [ ] HLS 地址不因前端 UI 改造而暴露到不应暴露的位置。
- [ ] 播放进度继续保存并恢复。
- [ ] 课时完成状态继续正常记录。
- [ ] 倍速、10 秒前进/后退、全屏继续可用。

### UI

- [ ] 首页桌面端正常。
- [ ] 首页手机端正常。
- [ ] 课程中心桌面端正常。
- [ ] 课程中心手机端正常。
- [ ] 学习页面桌面端正常。
- [ ] 学习页面手机端正常。
- [ ] 微信内置浏览器不出现横向滚动。
- [ ] 白色课程内容下播放器进度条仍清晰可见。
- [ ] 无封面课程不会出现空白/破碎卡片。

## 6. 本阶段执行原则

每次修改都：

1. 先读取当前生产文件和相关依赖。
2. 尽量做完整、可解释的结构性修改，而不是追加一个更高优先级的 CSS 补丁。
3. 修改完成后立即提交到 `wpui-v2`。
4. 提交后重新读取关键文件或比较提交，确认写入成功。
5. 不向 `main` 写入任何内容。
