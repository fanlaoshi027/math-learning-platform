## 2026-08-30 · 课程详情与学习页面职责收口

### 发现的问题

继续从 `main` 最新代码检查前台学习链路时发现：课程中心在存在 `course_id` 时直接调用 `mathcourse_course_player`，而课程详情目录中的可访问课时链接又指向 Tutor Lesson 的普通 permalink，导致“课程详情”和“学习页”存在两套入口。

项目当前产品结构已经明确：

```text
课程中心 → 课程详情/目录 → 专用学习页 → 视频播放
```

因此不应让课程详情页再次承担完整播放器职责。

### 本轮修改

1. `wp/wp-content/plugins/math-course/includes/Course/class-course-service.php`
   - 新增内部 `lesson_learning_url()`。
   - 所有课程目录中的可访问课时链接统一生成到“学习课程”页面。
   - URL 同时携带 `course_id` 与 `lesson_id`，保证学习页能明确定位课程和课时。
   - HLS 权限、签名、Progress 等业务逻辑没有改变。

2. `wp/wp-content/themes/math-course-theme/page-course-center.php`
   - `course_id` 存在时不再调用 `mathcourse_course_player`。
   - 改为调用 `mathcourse_course_directory`，使该页面明确承担“课程详情/目录”职责。
   - 播放器统一留给 `page-learning.php`。

### 解决的问题

现在前台核心路径统一为：

```text
课程中心
   ↓
课程详情
   ↓
点击可观看课时
   ↓
学习课程页
   ↓
MathCourse Video Player
   ↓
HLS Video Router
```

这样避免课程详情页和学习页重复输出课程信息，也符合当前备忘录确定的职责划分。

### 安全检查

本轮没有放宽任何视频权限：

- 课程目录仍由 `Access_Service` 决定课时是否可访问。
- `Course_Service` 仍只在最终观看权限通过后生成受保护 HLS 地址。
- 学习页播放器仍再次通过 `Course_Service` 获取最终播放数据。
- 未授权课时不会因为 URL 改为学习页而获得 HLS 地址。

### 测试情况

已完成 Git 当前代码静态链路检查，并核对：

- `Course_Service` → `Access_Service` → `Video_Router`
- 课程目录课时 URL
- `page-course-center.php` 的 `course_id` 分支
- `page-learning.php` 的 `lesson_id` 参数

当前没有真实 HLS 流媒体，因此暂未进行浏览器播放、拖动、Range、签名过期和 iPhone Safari 实测。

## 2026-08-31 · 修复学习页面 404

### 发现的问题

继续检查“课程详情 → 学习课程 → 播放器”链路时发现，代码已经把课时链接统一指向 `/学习课程/?course_id=...&lesson_id=...`，但学习页依赖 WordPress 数据库中实际存在名为“学习课程”的 Page。Git 中虽然存在 `page-learning.php` 模板，但模板文件本身不会自动创建 WordPress Page，因此在新测试站没有创建该页面时，访问学习 URL 会直接得到 404。

### 本轮修改

修改：`wp/wp-content/themes/math-course-theme/functions.php`

新增 `mc_ensure_learning_page()`：

- 在 WordPress `init` 阶段检查“学习课程” Page 是否存在。
- 不存在时自动创建发布状态的 Page。
- 使用 slug `学习课程`。
- 自动指定模板 `page-learning.php`。
- 创建后刷新 rewrite rules，避免新页面继续返回 404。
- 已存在页面不会重复创建。

同时补充主题对 `mathcourse_course_learning` shortcode 的识别，保持现有 `mathcourse_course_player` 主学习页实现不变。

### 本轮原则

没有修改 WordPress 核心、Tutor LMS 源码、HLS 权限、Video Router 或 Progress 逻辑。此次只修复学习页面入口缺失导致的 404。
