## 项目

- GitHub：`fanlaoshi027/math-learning-platform`
- 分支：`main`
- 产品：樊老师数学在线课程平台
- 技术：WordPress + Tutor LMS Pro 4.0.4 + MathCourse + MathCourse Theme

## 当前架构

```text
WordPress
  ↓
Tutor LMS Pro 4.0.4
  ↓
Tutor\\Adapter
  ↓
Course_Service
  ├─ Access_Service
  ├─ Progress_Service
  └─ Video_Router
  ↓
课程中心 / 课程详情 / 我的学习 / 学习页
```

Tutor LMS 负责底层 Course / Topic / Lesson 数据；MathCourse 负责本项目的课程业务、权限、试看、视频、学习进度和前台体验。不要重新制造完整 LMS。

## 前台 UI 当前方案

网站前台重新定义为两大课程类型：

1. **专题课**：围绕几何、方程、函数等专题进行系统突破。
2. **教辅配套视频课**：围绕具体教辅/教材，按章节逐题讲解。

视觉原则：

- 极简、专业、轻快，不做传统 LMS 商城化。
- 深海蓝为主色，活力橙作为少量强调色。
- 白色内容卡片 + 浅灰背景 + 大圆角 + 很轻的阴影。
- 手机优先，桌面端保持宽松留白。
- 不加入笔记、错题、社区、下载讲义、教师笔记、知识点等非核心模块。
- 不增加复杂动画和大型前端框架。

当前前台信息架构：

```text
首页
├─ 品牌 Hero
├─ 专题课 / 教辅配套 两大入口
└─ 课程库

课程中心
├─ 全部
├─ 专题课
├─ 教辅配套
└─ 年级筛选

课程详情
├─ 课程标题
├─ 学习进度
├─ 继续学习
└─ 课程目录

我的学习
├─ 已授权课程
└─ 每门课程进度 / 继续学习

学习页
├─ HLS 视频播放器
├─ 当前课时
├─ 上一课 / 下一课
└─ 课程目录
```

## 已完成核心工作

### Tutor / Course

- Tutor Adapter 已作为 Tutor API 统一适配层。
- Lesson → Course 归属统一通过 Adapter / Progress Service。
- Course Service 负责课程业务编排。
- Tutor Lesson Access 已统一走 Access Service。
- Preview 已统一走 Adapter。
- Course Service 创建 Video Router 时关闭 Hook 注册，避免重复注册 rewrite/template_redirect。
- 课程管理“新增课程”已接入 MathCourse 自有创建流程，不再指向旧的 `page=create-course`。
- 课程编辑器的 Tutor LMS 入口已改为标准 WordPress Course 编辑地址。
- 课程编辑器的课时视频字段已统一到标准 Meta：`_mathcourse_video_id`、`_mathcourse_hls_url`、`_mathcourse_page_number`。
- 课程编辑器读取旧版 `_mathcourse_video` / `_mathcourse_page` 作为兼容 fallback，保存时写入标准字段，避免历史课时突然丢数据。
- 课程编辑器现在可以直接填写 HLS 流媒体地址；HLS 地址使用密码框显示并仅服务器端保存，前台只取得短时受保护地址。

### 权限

- Access Service 作为最终课程/课时观看权限来源。
- 已授权用户可以观看授权课程。
- 未授权用户只能观看明确允许 Preview 的课时。
- 未授权状态不得向前端返回受保护 HLS 地址。
- Video Router 的 `get_protected_url()` 主动执行最终 `can_watch()` 校验，实际 HLS 请求进入 `handle()` 后仍再次检查观看权限。
- 旧版 `mathcourse_complete` AJAX 已改为统一调用 Progress Service，不能再绕过课程/课时权限和完成规则。
- Legacy `Complete_Service` 已改为兼容包装器，不再直接写 `mathcourse_learning`，并验证客户端传入的 course_id 与 Lesson 实际归属一致。
- `Access_Service` 的课时播放/试看权限现在额外要求 Course 和 Lesson 均为 `publish` 状态，并验证 Lesson 确实属于目标 Course，避免草稿/无效内容通过试看属性获得播放权限。
- `get_user_courses()` 现在过滤已过期的 active 授权，避免过期课程继续出现在学员课程列表。
- `Access_Service` 现在对同一请求中的用户+课程授权查询做内存级缓存，避免课程目录逐课时重复查询授权表；授权 `grant/revoke` 成功后会主动清除对应缓存。

### Video / HLS

- 已建立 `/math-video/{lesson}/{expires}/{signature}/` 网关。
- HMAC-SHA256 短期签名，默认 600 秒。
- 一级和多级 m3u8 会重写资源 URI。
- `.ts` / `.m4s` / `.aac` 等媒体请求重新验证签名和权限。
- Range / 206 / Content-Range 已有基础支持。
- EXT-X-MAP / EXT-X-KEY / EXT-X-MEDIA 等 URI 已纳入重写处理。
- 子 playlist URI 会按照声明它的 playlist 的路径解析。
- `get_protected_url()` 已增加最终 `can_watch()` 校验。

**尚未经过真实生产环境验证，不得宣称 HLS 防盗链已经完全生产级。**

### Progress / Player

- Progress Service 负责课时完成和课程完成百分比。
- 完成状态保存为用户 Meta：`mc_completed_lessons`。
- Lesson → Course 验证集中在 Progress Service。
- 播放到几分几秒与“课时完成”分开。
- 精确播放断点目前使用浏览器 localStorage，避免高频请求服务器。
- Player 在播放接近结尾且检测到真实播放后提交课时完成。
- 已修复 Player 的 `ended` 事件直接提交完成的问题：直接拖动/seek 到视频结尾不会立即把课时标记为完成，必须在最近一次 seek 后累计至少约 1.2 秒有效播放。
- Legacy `Tutor\\Complete` AJAX 已不再直接写学习表或信任客户端 `course_id`，统一委托 Progress Service。
- `Lesson_Status` 已统一读取 MathCourse Progress Service，不再通过 Tutor Adapter 查询另一套完成状态。
- Legacy `Learning\\Complete_Service` 已改为委托 Progress Service，旧调用不会再形成独立学习记录写入路径。
- Video Player 的 Video.js / player.js 资源现在只在实际渲染 `[mathcourse_video]` 播放器时加载，避免课程中心、普通页面等无播放器页面额外加载视频播放器资源。
- 课程学习页已增加轻量上一课 / 下一课导航，不增加数据库或额外接口。
- 课程播放器进度 UI 会在课时完成 AJAX 成功后即时更新。
- 课时完成 AJAX 只保存完成状态和返回当前课程进度，不再额外写入冗余的 `mc_last_completed_course` 用户 Meta。
- 当前播放器保持轻量 Video.js + 原生 video 控件方案，暂不加入反色、专用横屏、自定义复杂控制栏等非核心功能。
- 测试阶段明确以 HLS 流媒体作为实际播放路线；MP4 fallback 仅保留兼容能力，不作为当前测试标准。
