### 2026-08-30 · 本轮继续开发

#### MP4 / HLS 测试路线确认

经过讨论，测试阶段不制作或上传 MP4，**直接以 HLS 流媒体作为实际测试标准**。MP4 fallback 仅保留为 Tutor LMS 兼容能力，不再围绕它开发测试流程。

目标链路固定为：

```text
HLS m3u8 + 分片
    ↓
MathCourse Video Router
    ↓
短时签名 + 权限验证
    ↓
Video.js
    ↓
播放进度
    ↓
课时完成
    ↓
课程进度
```

正式上线和现在测试尽量使用同一条播放链路，这样真实测试结果更有意义。

#### AJAX / 权限检查

继续扫描 `wp_ajax_`、nonce、登录和权限链。当前 `Progress_Ajax` 要求用户登录并使用 `check_ajax_referer('mathcourse_progress_nonce', 'nonce')`，实际完成与课程归属验证交给 `Progress_Service`；Legacy `mathcourse_complete` 同样有 nonce，并委托 `Progress_Service`。

批量课时管理的创建、取消和 AJAX 分步任务也有管理员权限、nonce 以及课程 `edit_post` 权限检查。本轮没有增加重复的安全层，保持个人轻量网站原则。

#### Access 性能优化

在 `Access_Service` 中发现课程学习目录会逐课时调用权限判断；对于同一请求中的同一用户、同一课程，会产生重复授权查询。

增加请求级内存缓存：

```text
用户 ID + 课程 ID
        ↓
第一次查询数据库
        ↓
同一次请求后续直接使用缓存
```

`grant()` / `revoke()` 成功后会主动清除对应缓存。

没有引入 Redis、对象缓存服务、额外数据库表或复杂缓存层。

Git：`8722e12d` — `perf: cache course access checks within request`

#### HLS 网关静态检查

继续检查 `m3u8 → 子 playlist → ts/m4s/aac` 的链路，确认：

- 主 m3u8 使用短期签名。
- 子 m3u8 继续进入同一网关。
- 媒体分片请求再次验证签名和观看权限。
- Range 请求有基础处理。
- 相对路径按照当前 playlist 目录解析。
- `EXT-X-KEY`、`EXT-X-MAP`、`EXT-X-MEDIA` 等 URI 属性进入统一重写。
- 没有发现前台直接输出 `_mathcourse_hls_url` 的其他出口。

本轮没有为了理论优化而修改 HLS 核心代码，因为真实 HLS 文件尚未上传；后续必须通过真实 m3u8 和分片测试确认。

#### 发现并修复：课程编辑器视频字段不统一

检查后台课程编辑器时发现，课程编辑器原来使用：

```text
_mathcourse_video
_mathcourse_page
```

而通用课时 Meta 和播放器业务使用：

```text
_mathcourse_video_id
_mathcourse_hls_url
_mathcourse_page_number
```

如果继续保持两套字段，未来可能出现“后台填写了资源，但播放器读取另一套字段”的问题。

因此本轮将课程编辑器统一到标准字段：

```text
_mathcourse_video_id
_mathcourse_hls_url
_mathcourse_page_number
_mathcourse_preview
```

同时为了兼容已经创建的历史课时，编辑器读取时仍会 fallback：

```text
标准字段为空
    ↓
读取旧字段 _mathcourse_video / _mathcourse_page
```

保存时统一写入标准字段。

HLS 地址现在可以直接在 MathCourse 课程编辑器中填写：

- 输入框使用 password 类型，避免管理员在页面上长期明文显示。
- 保存到 `_mathcourse_hls_url`。
- 前台不直接输出该地址。
- 播放器最终使用 Video Router 生成的短时受保护地址。
- HLS 输入留空时保持已有地址，避免编辑课时其他字段时误删 HLS 地址。
